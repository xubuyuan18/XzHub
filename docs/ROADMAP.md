# XzHub 开发路线图

路线图用于控制范围，不代表严格发布日期。每个阶段必须具备可运行、可验证的结果后，才能进入下一阶段。

## Phase 0：仓库与开发规范

- [x] 创建公开仓库。
- [x] 添加 MIT License。
- [x] 添加项目说明和架构文档。
- [x] 添加 AI Coding 开发约束。
- [x] 配置 Issue 与 Pull Request 模板。
- [ ] 配置基础 CI。

完成标准：新贡献者能够理解项目目标、边界和提交规则。

## Phase 1：Windows 桌面壳

- [ ] 初始化 Tauri 2、React、TypeScript 和 Vite。
- [ ] 创建系统托盘图标。
- [ ] 左键托盘图标显示或隐藏窗口。
- [ ] 右键菜单支持显示、刷新、设置和退出。
- [ ] 点击窗口外部及按 Esc 时隐藏。
- [ ] 关闭按钮只隐藏窗口。
- [ ] 支持多显示器和不同任务栏方向。

完成标准：应用不包含真实监控功能，但托盘交互稳定可用。

## Phase 2：静态界面

- [ ] 创建总览页、历史页和设置页。
- [ ] 创建服务状态卡片。
- [ ] 支持在线、警告、离线、未知四种状态。
- [ ] 支持深色和浅色主题。
- [ ] 使用模拟数据完成用量进度和基础图表。

完成标准：所有核心界面可以通过模拟数据演示。

## Phase 3：本地数据层

- [ ] 集成 SQLite。
- [ ] 建立迁移机制。
- [ ] 实现服务配置增删改查。
- [ ] 保存应用设置和卡片排序。
- [ ] 接入 Windows Credential Manager。

完成标准：应用重启后配置保留，敏感凭据不进入数据库明文字段。

## Phase 4：Provider 与调度器

- [ ] 定义统一 Provider 接口。
- [ ] 实现 HTTP 状态 Provider。
- [ ] 实现通用 JSON Provider。
- [ ] 实现后台调度、超时、并发限制和失败重试。
- [ ] 支持手动刷新和缓存数据展示。

完成标准：窗口隐藏时仍能周期检查服务，单个服务失败不影响其他服务。

## Phase 5：VPS Agent

- [ ] 定义 Agent API 协议。
- [ ] 实现 Linux Agent 最小版本。
- [ ] 支持 CPU、内存、磁盘、负载和运行时间。
- [ ] 支持鉴权和 TLS。
- [ ] 客户端展示 VPS 指标。

完成标准：至少一台 Linux VPS 可以通过 Agent 被稳定监控。

## Phase 6：历史与通知

- [ ] 保存有限历史快照。
- [ ] 绘制趋势图。
- [ ] 配置阈值告警。
- [ ] 接入 Windows 原生通知。
- [ ] 实现通知冷却和状态恢复提示。

## Phase 7：发布准备

- [ ] 完成图标与安装包。
- [ ] 配置自动更新。
- [ ] 配置 Release 工作流。
- [ ] 完成第三方许可证清单。
- [ ] 编写用户文档和故障排查指南。
- [ ] 发布首个预览版本。

## 后续候选方向

以下内容需在 MVP 稳定后讨论：

- Provider 插件机制。
- Prometheus、Cloudflare 等原生集成。
- Webhook 和通知渠道。
- 可选云同步。
- 团队共享面板。
- macOS 或 Linux 客户端。
